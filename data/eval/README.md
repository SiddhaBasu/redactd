# Evaluation sets

JSONL, one document per line: `{id, source, domain, text, spans: [{start, end, label, tier}]}`. Offsets are Unicode
code points. `tier` is `direct` or `indirect` (see `bench/taxonomy.py`). Every document is synthetic; none contains
real personal data.

## Rules

* **Held-out sets are never used to tune rules, thresholds, prompts or word lists.** Do not read their documents or
  their individual misses. `bench/report.py --miss` withholds text for held-out sets on purpose.
* Dev sets may be inspected and tuned on. Numbers on dev sets are optimistic by construction.
* `eval_gretel_fin_holdout` was built by the previous maintainer; `bench/gold_policy.py` (the policy-adjusted
  labels) predates this file and may have been informed by it. `eval_fin_holdout2` is the cleanest finance check.
* `eval_adversarial`: value pools are disjoint from the training generator's, and half of the templates
  (`tpl_in_train: false`) are never rendered for training. The report shows the two halves separately.
* `eval_gretel_en` leaves out source documents containing strings in live provider token formats (SendGrid, Square,
  Slack …): GitHub push protection rejects them even though they are synthetic. 4 of the first 300 sampled documents
  were replaced by the next ones in the same seeded shuffle, before any evaluation.
* Training data (`data/processed/`, not committed) comes only from the *train* splits of the datasets above plus
  `bench/make_adversarial.py train`.

Rebuild: `python bench/prepare.py && python bench/make_holdout.py && python bench/make_eval_sets.py && python bench/make_adversarial.py eval`
